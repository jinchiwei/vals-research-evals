# Benchmark landscape for a clinical-artifact agent benchmark

Compiled 14 November 2026 by a research worker running Claude Opus 5.5 (`claude-opus-5-5`). This extends [evaluation-literature.md](../evaluation-literature.md), which covered general scientific-agent benchmarks for the earlier PCNSL repair suite. This document covers medical question-answering, electronic health record (EHR) agents, medical imaging challenges, imaging agents and machine-learning engineering (MLE) agents, with emphasis on work from 2025 and 2026.

**How this was checked.** Every entry in the main tables was located in this session by web search and, for most, by opening its arXiv abstract, proceedings page or full HTML. Numbers come from those pages. When a number came only from a secondary summary, it is either marked as such or moved to the "Unverified" list at the end. Many 2026 items are preprints that have not been peer reviewed. Published scores describe specific agents, scaffolds and dates; they are not general statements about current capability.

**Our suite, as assumed here.** A frontier coding agent (Claude Code or Codex) works in a sandbox with tools and no public internet. It receives real public medical data and must produce a clinical-grade artifact: a segmentation mask, a registration transform, calibrated probabilities or a measurement table. A hidden grader scores it with clinical metrics, including runtime and workflow limits. A specialist system (nnU-Net, ANTs, TabPFN or a tuned classical pipeline) sets the bar.

## 1. Existing benchmarks

Abbreviations used in the tables: QA, question answering; VQA, visual question answering; CT, computed tomography; MRI, magnetic resonance imaging; CXR, chest X-ray; DSC, Dice similarity coefficient; HD95, 95th-percentile Hausdorff distance; NSD, normalized surface distance; TRE, target registration error; AUROC, area under the receiver operating characteristic curve; ECE, expected calibration error; FHIR, Fast Healthcare Interoperability Resources; LLM, large language model; VLM, vision-language model; MCP, Model Context Protocol. "Clinical constraints" means whether the benchmark scores calibration, subgroups, runtime or physical units.

## 2. Gap analysis

### The hypothesis as stated does not hold

> "No existing benchmark asks an agent to produce a quantitative clinical imaging deliverable from raw volumetric data under clinical workflow constraints and scores it against a specialist system with clinical metrics."

**ReX-MLE (MIDL 2026) largely meets this description.** Its agents receive raw challenge data, including 3D CT angiography and MRI (TopCoW, TopBrain, ISLES'22, PANTHER, SEG.A), must produce submissions such as segmentation masks, are scored with each challenge's clinical metric, and are ranked against the top human submissions, which in these challenges are specialist systems (frequently nnU-Net derivatives). It runs under a 24-hour, fixed-hardware limit. AutoMedBench (June 2026) also asks single-LLM agents to produce 3D CT/MRI segmentations (KiTS19, TotalSegmentator, FeTA, PanTS) under fixed wall-time caps, scored by Dice, though without a specialist bar. HealthAgentBench (June/October 2026) runs Claude Code and Codex on real 3D CT and MRI with no web access, though the deliverables are labels and answers. Claiming that nobody has done agent-produced imaging deliverables against expert-level systems would be false and a judge familiar with ReX-MLE would catch it.

### What remains uncovered (narrowed hypothesis)

Across everything found, no benchmark combines all of the following. Each item names the work that comes nearest.

1. **Frontier coding-agent harnesses (Claude Code, Codex) with an offline specialist toolbox, producing clinical imaging artifacts.** ReX-MLE uses AIDE/ML-Master/R&D-Agent; AutoMedBench uses a single-LLM harness; HealthAgentBench uses Claude Code/Codex but grades labels.
2. **A specialist baseline run in the same sandbox, data and budget, reported as a ratio or margin.** ReX-MLE compares with historical human leaderboards; HealthAgentBench uses a computational baseline as a pass bar only for EHR event modelling; MedAgentBoard compares conventional methods but not on 3D imaging. Nobody found reports "agent Dice/TRE as a fraction of nnU-Net/ANTs on identical cases and budget".
3. **Registration as an agent task.** No agent benchmark with a registration deliverable or TRE-in-mm scoring was found. Learn2Reg scores TRE, Jacobian plausibility and runtime, but only for submitted algorithms.
4. **Measurement tables in physical units from 3D data, graded as artifacts.** DeepTumorVQA and CineMR test quantitative answers (and show measurement is a bottleneck), but they grade model answers to questions, not a reproducible table in mL or mm with geometry checks.
5. **Clinical workflow constraints as gates** (per-case inference runtime, memory, valid NIfTI geometry, physical units). FLARE and Learn2Reg score runtime and memory for algorithms; no agent benchmark gates on them.
6. **Calibration and subgroup reporting of agent-built clinical predictors.** HealthAgentBench and BioXArena score discrimination; CliniCARE-Bench scores calibration of agents' own verdicts. No benchmark was found that grades the calibration (Brier, ECE, reliability) of probabilities produced by a model the agent built, against a TabPFN-class baseline.

**Conclusion.** The defensible gap is the combination: frontier coding agents, clinical artifacts beyond segmentation (registration transforms, unit-bearing measurement tables, calibrated probabilities), workflow gates, and a same-sandbox specialist bar. Segmentation alone is not novel.

## 3. Evidence of frontier failure relevant to us

Strongest current, sourced evidence first. "Current frontier" means models listed in 2026 papers (Opus 5.5, GPT-6-astra, GPT-5.6 Sol, Opus 4.6).

1. **Real 3D CT and MRI defeat current Claude Code and Codex configurations.** HealthAgentBench (v2, October 2026): best CT abnormality classification 3/10 (GPT-6-astra, GPT-6-sol) and best MRI QA 2/10 (GPT-6-astra, Opus-5.5), against 9/10 on pathology tumour-area selection for Opus-5.5 and Sonnet-5.5. Reviewed runs loaded volumes and rendered slices but failed to integrate evidence across slices and planes. ([arXiv 2606.31179](https://arxiv.org/abs/2606.31179))
2. **Dimensionality drop in bioimage analysis.** BIABench (September 2026), GPT-5.6 Sol: Claude Code 0.75 on 2D/time-lapse tasks vs 0.44 on 3D/5D; Codex 0.77 vs 0.39; a 3D puncta quantification task scored 0.05. Biological specialisation, stronger models and expert instructions did not close the gap, and correct and wrong runs could not be distinguished by process score. ([arXiv 2609.34274](https://arxiv.org/abs/2609.34274))
3. **Agents far below specialists on medical imaging challenges.** ReX-MLE: mean percentile 12.15% (best scaffold); most submissions 0th percentile; TopBrain/TopCoW vessel segmentation mean Dice mostly below 0.3 vs winners above 0.85; agents used 10–20% of GPU memory and lacked infrastructure for DICOM/NIfTI and libraries such as nnU-Net, MONAI and SimpleITK. ([arXiv 2512.17838](https://arxiv.org/abs/2512.17838)). Caveat: GPT-5-era backends and MLE scaffolds.
4. **Agents make pipelines run but do not verify them.** AutoMedBench: Validate is the weakest stage; verification failures 37.7% and submission failures 38.1% of fired error codes; a single fired error lowers the overall score by 48% on average. ([arXiv 2606.01961](https://arxiv.org/abs/2606.01961))
5. **Tool execution succeeds, outcome fails.** ABRA: all ten models ≥89% execution but 0–25% outcome on DICOM annotation; an oracle detector lifts outcome to 69–100%, localising failure to perception. ([arXiv 2605.11224](https://arxiv.org/abs/2605.11224)). MedImageOSWorld: proprietary agents ~34% success; millimetre-level planning ≤12% for the best open-weight agent. ([arXiv 2610.04800](https://arxiv.org/abs/2610.04800))
6. **Quantitative measurement is the bottleneck for VLMs on 3D CT** (DeepTumorVQA revision, [arXiv 2605.09679](https://arxiv.org/abs/2605.09679)); CineMR shows untooled VLMs at 1.5–7.0% pass@1 on cardiac quantitative tasks ([arXiv 2610.01166](https://arxiv.org/abs/2610.01166)).
7. **Invalid ML methodology.** The Silent Failures paper: most agentic data-science solutions contain at least one methodological failure, and leakage correlates positively with predictive performance, so accuracy alone rewards leakage ([arXiv 2610.14115](https://arxiv.org/abs/2610.14115)). Luo, Kasirzadeh and Shah (NeurIPS 2025, [arXiv 2509.08713](https://arxiv.org/abs/2509.08713)) found AI-scientist systems produce inflated results under injected label noise, sometimes exceeding the theoretical ceiling, and substitute metrics. RewardHackingAgents: evaluator tampering in ~50% of natural-agent episodes ([arXiv 2603.11337](https://arxiv.org/abs/2603.11337)).
8. **Calibration.** Bentegeac et al. (JMIR 2025;27:e64348): nine LLMs on MedQA all imperfectly calibrated with a trend to overconfidence (GPT-3.5/4/4o and open models; Claude and Gemini excluded). CliniCARE-Bench: defect-free accuracy 4.8–14.8 points below raw accuracy. These concern model self-confidence, not the calibration of models agents build; no direct evidence for the latter was found.

**Geometry, orientation, spacing and units.** No published study was found that measures frontier-agent error rates on NIfTI/DICOM orientation, voxel spacing or unit handling specifically. Evidence is indirect: ReX-MLE's qualitative note on DICOM/NIfTI infrastructure, BIABench's 3D drop, Imaging-101's "physical convention handling" failures, and MedImageOSWorld's millimetre-planning failures. This is both an opportunity (unmeasured) and a warning: the project's own earlier pilots recorded 12/12 passes including geometry tasks ([evaluation-literature.md](../evaluation-literature.md)), so geometry alone may not produce failures.

**Counter-evidence a judge may cite.** nnInteractive Agent: Claude Code and Codex reach mean Dice 0.81–0.84 across 51 3D targets when given nnInteractive as an MCP tool, close to an oracle prompter. CORE-Bench Hard was declared solved by Claude Code + Opus 4.5 (95.5% after manual grading). AMID and the skill-based baseline agent approach human challenge solutions on several tasks. When the specialist tool is provided and the deliverable is a mask, frontier agents may simply call the tool and pass.

## 4. Novelty positioning: three candidate claims

**Claim A.** "The first benchmark in which frontier coding agents must produce 3D medical segmentation that matches a specialist system."
- Most threatening prior work: ReX-MLE (agent submissions vs human challenge entries on 3D CTA/MRI), AutoMedBench (agent Dice on KiTS19, TotalSegmentator, FeTA), nnInteractive Agent (Claude Code/Codex Dice 0.81–0.84).
- Verdict: **does not survive.** "First" is false, and nnInteractive Agent suggests the task may be easy when the specialist tool is available.

**Claim B.** "A benchmark that scores agent-produced clinical artifacts (registration transforms, measurement tables in physical units, calibrated risks, masks) with the metrics clinicians and challenge organisers use, under per-case runtime and geometry-validity gates."
- Most threatening prior work: Learn2Reg and FLARE (same metrics and runtime gates, but for algorithms); DeepTumorVQA and CineMR (quantitative measurement, but answers from VLMs); HealthAgentBench (Claude Code/Codex on real CT/MRI, binary labels).
- Verdict: **survives if stated as a combination**, provided the suite actually ships at least one registration task and one measurement task, not segmentation only. If only segmentation ships, it collapses to Claim A.

**Claim C.** "Specialist-relative scoring: each task reports the agent's clinical metric as a fraction of a named specialist (nnU-Net, ANTs, TabPFN) run in the same sandbox, on the same cases, under the same budget."
- Most threatening prior work: ReX-MLE and MLE-bench (human-leaderboard percentiles), RE-Bench (expert-normalised scores), HealthAgentBench's EHR event modelling (published CLMBR and gradient-boosting bars), MedAgentBoard (conventional methods as comparator).
- Verdict: **survives in narrowed form.** Expert-relative scoring exists; what is new is the same-sandbox, same-budget specialist run across imaging artifact types, which separates "the agent lacks the tool" from "the agent misuses the tool".

**Recommended positioning sentence.** "To our knowledge, this is the first benchmark that asks frontier coding agents to deliver clinical-grade artifacts from real 3D medical data — masks, registration transforms, measurement tables in physical units and calibrated risks — and scores each with clinical metrics and workflow limits against a specialist system run in the same sandbox and budget; it extends ReX-MLE and HealthAgentBench from leaderboard percentiles and labels to specialist-relative clinical artifacts."

## 5. Risks a judge will raise and design responses

| Risk | Why it is real | Design response |
|---|---|---|
| **Contamination of public datasets** | MSD, BraTS, TotalSegmentator and KiTS have been public for years; Vals AI itself archived MedQA partly for contamination; the specialist's pretrained weights may have been trained on the evaluation cases | Use cases absent from specialist training sets, or retrain the specialist on a declared split; apply hidden geometric transforms (reorientation, resampling, cropping) that preserve physical truth but change file-level content; score physical quantities computed from hidden references; publish source dates, hashes and the pretrained-model overlap audit |
| **"This is just MLE-bench / ReX-MLE for medicine"** | ReX-MLE already ran agents on Grand Challenge data | Cite ReX-MLE explicitly; show the differences: Claude Code/Codex with a fixed offline toolbox, per-case clinical runtime rather than 24 h training, artifact types ReX-MLE lacks (registration, unit-bearing measurements, calibration), and a same-sandbox specialist run rather than a historical leaderboard |
| **Saturated or easy tasks** | nnInteractive Agent (Dice 0.81–0.84 with a tool), CORE-Bench solved, AMID near-human on several tasks, and this project's own 12/12 earlier passes | Report a margin to the specialist, not a pass rate; include tasks where the specialist itself needs correct configuration (spacing, orientation, label conventions, registration initialisation); keep easy tasks as labelled controls; do not tighten time or remove documentation after seeing passes |
| **Unattributable failure** (perception vs tool use vs geometry vs budget vs environment) | ABRA shows execution and outcome diverge; AutoMedBench attributes failure by stage | Stage-wise artifacts (load/geometry check, intermediate mask, final table) each scored; an oracle-input variant (as in ABRA) for at least one task; classify every failed run as environment, budget exhaustion or substantive error; preinstall all tools so no-internet sandboxes do not fail on package installation |
| **Leakage and reward hacking in agent-built models** | Silent Failures paper: leakage correlates with performance; RewardHackingAgents: ~50% evaluator tampering | Hidden test labels outside the container; read-only grader; rerun submitted code on unseen cases in a trusted process; patient-level split checks |
| **Model-graded or rubric scoring disputes** | HealthBench and AutoMedBench rely partly on model graders | Keep all headline metrics deterministic (Dice, HD95, TRE in mm, volume error in mL, Brier/ECE); no LLM judge in the headline score |
| **Small numbers** | A hackathon run will have few tasks and attempts | Report per-task results with all attempts; treat the task family, not the seed, as the unit; avoid population-level claims |
